# 风格规范 — 项目文档

## 语气
- 第三人称、陈述句、事实导向
- 避免营销词："革命性"、"颠覆性"、"极致"、"行业领先"
- 避免冗词："众所周知"、"毋庸置疑"、"如上所述"

## 结构
- 每个一级章节开头用 1-2 句话概括本节要点
- ≥3 个并列项使用项目符号列表
- 对比、字段说明、错误码等结构化数据使用表格
- 代码块必须标注语言（```ts、```json、```http 等）

## 术语
- 首次出现的缩写必须给出全称，如 "灰度发布 (Canary Release)"
- 全文术语翻译保持一致（一旦定为"接口"就不再混用"API"）
- 优先使用行业通用术语，避免自造名词

## 标注
- 未确认信息统一使用 `<TBD: 说明>` 标记，便于后续搜索
- 风险、假设、待决问题集中放在文末"风险与开放问题"章节
